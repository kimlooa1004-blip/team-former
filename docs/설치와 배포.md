## 1단계. Supabase 프로젝트 만들기 (DB)

> 공고 4.2절: 6장 실습에서 만든 프로젝트를 재사용한다. 아직 만들지 않았다면 지금 만들고,
> 그 프로젝트를 6장 실습에도 쓴다. **새 프로젝트를 두 개 만들지 않는다**(무료는 2개까지).

1. `supabase.com` 에 가입하고 새 프로젝트(New project)를 만든다.
2. 만들 때 정하는 **Database Password 를 따로 적어 둔다.** 다시 볼 수 없다.
3. 프로젝트가 다 만들어지면 **Connect**(또는 Project Settings → Database)에서
   연결 문자열을 연다.
4. **Session pooler** 의 URI 를 복사한다. `postgresql://postgres.xxxx:[YOUR-PASSWORD]@...pooler.supabase.com:5432/postgres` 같은 꼴이다.
5. 복사한 주소의 `[YOUR-PASSWORD]` 부분을 2번에서 적어 둔 비밀번호로 바꾼다.
   이게 `DATABASE_URL` 이다.

> 비밀번호에 `@ : / ?` 같은 글자가 있으면 주소가 깨진다. 그럴 땐 Supabase 에서
> 비밀번호를 영문과 숫자만으로 바꾸는 게 편하다.

테이블은 따로 만들 필요가 없다. 앱이 처음 켜질 때 `schema.sql` 을 그대로 실행한다.
직접 만들어 보고 싶으면 Supabase 의 SQL Editor 에 `schema.sql` 내용을 붙여 넣고 Run 해도 된다.

## 2단계. 오픈라우터 키 받기

1. `openrouter.ai` 에 가입한다.
2. Keys 에서 새 키를 만든다. `sk-or-v1-...` 로 시작한다. **이게 `OPENROUTER_API_KEY` 다.**
3. Models 에서 이름이 `:free` 로 끝나는 텍스트 생성 모델 3개를 고른다.
   `README.md` 4항에 적어 둔 기본 모델 3개가 아직 있는지 확인하고, 없으면 다른 걸로 바꾼다.
   바꿀 때는 코드를 고치지 말고 Secrets 에 `MODEL_1`, `MODEL_2`, `MODEL_3` 을 넣으면 된다.

> 무료 모델은 **계정마다 하루 50회, 분당 20회**다. 실패한 호출도 횟수에 들어간다.
> 채점 기간(11/3~11/4)에는 채점자가 루아 님 키로 AI를 부르므로, **그 이틀은 하루 30회 이상을

## 3단계. 내 컴퓨터에서 먼저 돌려 보기

```bash
pip install -r requirements.txt
```

`.env.example` 을 복사해 **`.env`** 로 저장하고 값을 채운다.

```
OPENROUTER_API_KEY="sk-or-v1-..."
DATABASE_URL="postgresql://..."
ADMIN_PASSWORD="직접 정한 비밀번호"
```

> 파일 이름은 정확히 `.env` 여야 한다. 메모장이 `.env.txt` 로 저장하면 `.gitignore` 가
> 걸러 내지 못해 키가 깃허브에 올라간다(-3점). 저장한 뒤 이름을 꼭 확인한다.
> `.env` 파일을 두 번 눌러 열지 않는다.

```bash
streamlit run streamlit_app.py
```

브라우저가 열리면 `admin` 과 위에서 정한 비밀번호로 로그인하고,
`samples/쉬움.csv` 를 올려 팀 수 3으로 시작해 본다.

## 4단계. 깃허브 비공개 저장소 만들고 올리기

1. 깃허브에서 **Private** 저장소를 만든다 (이름은 아무거나, 예: `team-former`).
2. 이 폴더에서:

```bash
git remote add origin https://github.com/<내아이디>/<저장소이름>.git
git push -u origin main
```

> 이미 커밋은 되어 있다. `.env` 는 커밋에 들어 있지 않다.
> 올린 뒤 깃허브에서 `.env` 가 안 보이는지 눈으로 한 번 확인한다.

## 5단계. Streamlit Community Cloud 배포

1. `share.streamlit.io` 에 깃허브 계정으로 로그인한다.
2. **비공개 저장소를 읽을 수 있게 먼저 허락한다**:
   Workspace settings → Linked accounts → Private access 옆 **Connect here**.
   이걸 안 하면 저장소가 목록에 안 뜬다.
3. Create app → 저장소를 고르고,
   - Branch: `main`
   - Main file path: `streamlit_app.py`
4. **Advanced settings → Secrets** 에 아래를 넣는다. `이름 = "값"` 꼴이다.

```toml
OPENROUTER_API_KEY = "sk-or-v1-..."
DATABASE_URL = "postgresql://..."
ADMIN_PASSWORD = "직접 정한 비밀번호"
```

> 브라우저 자동 완성이 예전 값을 채우면 지우고 다시 쓴다.

5. 배포가 끝나면 앱의 **Settings → Sharing** 에서
   "Who can view this app" 을 **"This app is public and searchable"** 로 바꾸고 Save changes.
6. **시크릿 창(로그인 안 한 브라우저)으로 배포 주소를 열어 로그인 화면이 보이는지 확인한다.**
   채점 프로그램은 로그인하지 않은 브라우저로 앱을 연다. 이게 안 되면 시나리오 점수가 0점이다.

## 6단계. DB 일시정지 막기 (0.5점)

저장소 → Settings → Secrets and variables → Actions → New repository secret

- Name: `DATABASE_URL`
- Secret: 1단계에서 만든 주소 그대로

그다음 Actions 탭에서 **keep-supabase-awake** 를 열고 **Run workflow** 를 한 번 눌러
초록색으로 성공하는지 확인한다. 이후 매일 자동으로 돈다.

## 7단계. 연습용 시나리오 직접 해 보기

배포한 앱에서 부록 1 → 2 → 3 차례로 해 본다. 브라우저 창을 여러 개(또는 시크릿 창을
여러 개) 띄워 학생마다 따로 로그인한다.

**이때 꼭 남겨야 할 것** (README 5항과 7항에 넣을 증거다. 꾸며 내면 시나리오 밖 점수 0점):

- AI 배정 중 `assign_status` 화면 캡처 — 몇 차 모델을 기다리는지 보이는 장면
- AI가 실패한 장면 (시간 초과, 429 오류, 빈 응답, 검사 실패 등)
- 관리자 화면 아래 **"비밀 값과 AI 호출 기록"** 을 펼치면 나오는 표 캡처
- 이상하다고 느낀 장면과 그게 몇 단계였는지

캡처 파일은 저장소에 `img/` 폴더를 만들어 넣고, `README.md` 5항과 7항에 경로를 적는다.
