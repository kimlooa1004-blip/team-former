# PRD — 팀 프로젝트를 위한 팀 편성 웹 앱

작성자: 김루아 (한양여자대학교 빅데이터과)
문서 상태: 중간 과제 제출본

## 1. 왜 만드는가

팀 프로젝트의 팀을 교수가 짜 주면 학생의 뜻이 들어가지 않고, 학생들끼리 자유롭게 짜면
역할이 한쪽으로 쏠리거나 끝까지 팀을 못 구하는 학생이 남는다.

이 앱은 **학생들이 스스로 팀을 고르되, 팀이 갖춰야 할 조건은 앱이 지켜 주는** 중간 지점을
만든다. 마지막에 남은 학생은 AI가 배정안을 내고, 그 답이 규칙에 맞는지는 앱이 검사한다.
AI의 말을 그대로 믿지 않고 앱이 규칙으로 걸러 내는 것이 이 앱의 핵심이다.

## 2. 쓰는 사람

| 사용자 | 하는 일 |
| --- | --- |
| 학생 | 학번과 비밀번호로 로그인한다. 팀 목록과 팀원, 팀원의 주·보조 역할을 본다. 팀에 지원한다. 내 팀에 들어온 지원에 찬성 또는 거부를 누른다. |
| 관리자(교수) | 학번 `admin` 으로 로그인한다. 명단을 올려 처음 상태를 만든다. 모집을 마감한다. 마감 뒤 남은 학생의 배정안을 받아 확인하고 확정한다. |

관리자 계정은 앱이 시작할 때 비밀 값 `ADMIN_PASSWORD` 로 만들거나 비밀번호를 갱신한다.
명단을 다시 올려도 관리자 계정은 남는다.

## 3. 다루는 것

### 3.1 역할

역할은 6개다: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자.
학생마다 **주 역할 1개와 보조 역할 0~2개**가 명단 CSV에 정해져 있고 학생이 바꾸지 못한다.

- **주 역할**은 한 팀 안의 중복을 따지는 기준이다.
- **보조 역할**은 필수 포함 역할을 맡을 수 있는지 따질 때만 쓴다.

### 3.2 팀 규칙

| 규칙 | 내용 |
| --- | --- |
| 팀 수 | 관리자가 명단을 올릴 때 정한 수만큼 만든다 (팀1, 팀2, …) |
| 인원 | 확정한 구성에서 모든 팀이 2~4명이어야 한다. 빈 팀은 없다 |
| 주 역할 중복 | 주 역할이 같은 학생이 한 팀에 2명 이상이면 안 된다 |
| 필수 포함 역할 | 모든 팀에 기획자와 웹 프로그래머가 **서로 다른 사람으로** 1명씩 있어야 한다. 주 역할이든 보조 역할이든 상관없다 |

한 학생이 기획자와 웹 프로그래머를 둘 다 할 수 있어도 **하나로만 센다**.

### 3.3 지원과 투표

| 상황 | 결과 |
| --- | --- |
| 빈 팀에 지원 | 투표할 팀원이 없으므로 바로 승인 |
| 팀원이 있는 팀에 지원 | 대기. 그 팀의 팀원 모두가 투표한다. 투표할 사람은 **투표하는 때의** 팀원이다 |
| 모든 팀원이 찬성 | 승인 직전에 규칙을 다시 검사하고, 통과하면 승인 |
| 한 명이라도 거부 | 다른 팀원을 기다리지 않고 바로 거절 |
| 한 학생의 지원 | 결과가 나오기 전에는 다른 팀에 지원할 수 없다 |
| 투표 바꾸기 | 한 번 투표하면 바꿀 수 없다 |

**막힘과 거절은 다르다.** 막힘은 지원을 아예 접수하지 않은 것이고(DB에 남기지 않는다),
거절은 접수되어 대기 중이던 지원이 떨어진 것이다.

### 3.4 마감과 배정

1. 관리자가 모집을 마감한다. 그 뒤로는 지원과 투표를 할 수 없다.
2. 마감 때 대기 중인 지원은 거절된다. 1명뿐인 팀의 학생은 팀에서 빠진다.
3. 관리자가 AI 배정을 누르면, 앱이 AI에게 지금의 팀 구성과 팀이 없는 학생, 규칙을 보내
   배정안을 받는다. **이미 팀에 있는 학생은 옮기지 않는다.**
4. 앱이 배정안을 다섯 가지로 검사한다: 빠짐없이 배정됨 / 한 팀에만 배정됨 / 모든 팀 2~4명 /
   주 역할 중복 없음 / 필수 포함 역할 충족.
5. AI가 응답하지 않거나 검사를 통과하지 못하면 2차, 3차 모델로 넘어간다. 모델 하나에
   120초를 넘기면 끊는다.
6. 3차까지 실패하면 앱이 스스로 배정한다.
7. 검사를 통과한 배정안만 관리자에게 보여 주고, 확정하면 DB에 저장한다.
8. 규칙을 지키는 배정이 아예 없으면 배정안을 만들지 않고 그 사실과 이유를 보여 준다.

## 4. 화면

### 4.1 로그인 화면
학번 칸, 비밀번호 칸, 로그인 단추. 비밀번호가 틀리면 들어갈 수 없다.

### 4.2 학생 화면
- 로그인한 사람 표시
- 단추를 누른 결과 안내 — **"승인", "대기", "거절", "막힘"** 가운데 하나로 시작한다
- 팀 목록: 팀마다 팀원의 이름과 주·보조 역할. 내 팀은 구별되게 표시하고, 팀이 없으면
  "아직 팀이 없음"을 보여 준다
- 팀마다 지원 단추. 이미 팀이 있거나, 결과를 기다리는 지원이 있거나, 마감되었으면
  단추를 비활성화한다
- 내 팀에 들어온 지원마다 찬성·거부 단추. 이미 투표했으면 비활성화하고 "내 투표: 찬성"처럼 보여 준다
- 팀이 없는 학생 목록

### 4.3 관리자 화면
명단 CSV 올리기, 팀 수, 처음 상태 만들기, 모집 마감, AI 배정, AI 배정 진행 안내,
배정안 표, 배정안 확정, 팀이 없는 학생 목록.

### 4.4 다른 사람의 변경 보기
다른 학생의 지원이나 투표가 **3초마다 저절로** 화면에 나타난다. 함께 둔 새로 고침 단추로
즉시 다시 그릴 수도 있다.

## 5. 지키기로 한 것

- 비밀번호는 해시(bcrypt)로 저장한다. 원래 값을 DB에 남기지 않는다.
- 오픈라우터 키, DB 주소, 관리자 비밀번호는 코드에 적지 않고 `.env` / Streamlit Secrets 에 둔다.
  화면과 로그에 절대 출력하지 않는다.
- 학생 계정으로는 관리자 기능을 쓸 수 없다.
- 테이블 이름은 모두 `tf_` 로 시작한다.
- 실제 사람의 이름과 학번은 쓰지 않는다. 가상 명단만 쓴다.

## 6. 다 됐다고 할 수 있는 조건

1. 관리자가 명단 CSV와 팀 수를 넣으면 앱 상태가 처음부터 다시 만들어진다.
2. 연습용 시나리오 3개(부록 1~3)의 모든 단계에서 결과 안내의 첫 단어가 기대 결과와 같다.
3. 마감 뒤 배정하고 확정했을 때, 모든 팀이 2~4명이고 주 역할이 겹치지 않으며
   기획자와 웹 프로그래머가 서로 다른 사람으로 들어 있다.
4. AI 모델이 실패해도 2차·3차로 넘어가고, 3차까지 실패해도 앱이 규칙을 지키는 배정을 낸다.
5. 브라우저를 새로 열어도 확정한 팀 구성이 남아 있다.

## 7. 하지 않기로 한 것

- 구글 로그인(`st.login`): 채점자가 학생 여러 명으로 로그인할 수 없어 쓰지 않는다.
- 학생이 자기 역할을 바꾸는 기능: 역할은 명단에서 정해진다.
- 확정 뒤 팀을 다시 편성하는 기능: 과제 범위 밖이다.
- 무료 모델 자동 연결 라우터(`openrouter/free`): 다음 모델로 넘기는 처리를 직접 만드는 것이
  과제의 일부라 쓰지 않는다.
